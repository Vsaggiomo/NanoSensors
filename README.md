The site is built with **Jupyter Book 2 / MyST** and deployed to **GitHub Pages** by GitHub Actions.

The chapter contains nine interactive `ipywidgets` + `matplotlib` figures. In Binder, choose `Run` → `Run All Cells`; if Jupyter asks whether to trust the notebook, click **Trust**. To hide the code in the interactive notebook, use **View → Collapse All Code**. The sliders require a live Jupyter kernel, so the interactive version opens in **Binder** (Jupyter Notebook interface). The GitHub Pages site is the reading version, with a static preview of each interactive figure and code collapsed behind a **Source** toggle.

> **Why not in-page execution?** MyST/Thebe can execute the notebook against a Binder kernel, but the current MyST theme does not render `ipywidgets` controls reliably: the widget outputs are replaced by placeholders. The Binder route uses the full Jupyter widget stack, so the sliders work. In-page support may improve as MyST/Thebe matures.

## Repository layout

```text
.
├── myst.yml                  # MyST / Jupyter Book configuration (TOC, theme)
├── index.md                  # landing page
├── chapter-01.ipynb          # generated reading copy used by MyST
├── source/
│   └── chapter-01.ipynb      # clean editable notebook for Binder / Colab
├── figures/                  # figures and default-state previews
├── scripts/
│   ├── prepare_book.py          # source/ -> reading copy
│   ├── generate_previews.py     # regenerate default-state previews
│   └── strip_widget_outputs.py  # remove stale saved widget outputs
├── requirements.txt          # pinned Binder environment
├── LICENSE                   # CC BY-NC 4.0
├── CITATION.cff              # citation metadata
└── .github/workflows/deploy.yml
```

`source/chapter-01.ipynb` is the notebook to edit. `chapter-01.ipynb` is generated by `scripts/prepare_book.py` and should not be edited directly.

## Reading locally

```bash
# Node 18+ and npm are required by MyST
npm install -g mystmd@1.11.0

# from this repository root
myst start
```

Or with the Jupyter Book CLI:

```bash
pip install jupyter-book
jupyter-book start
```

The site is served at <http://localhost:3000> by default.

## Build the static site

```bash
myst build --html
```

The output is written to `_build/html`. For GitHub Pages, set the base URL first:

```bash
BASE_URL=/NanoSensors myst build --html
```

## Regenerating the reading copy and previews

After editing `source/chapter-01.ipynb`:

```bash
# 1. regenerate the static previews from the default widget values
python scripts/generate_previews.py

# 2. optionally remove stale saved widget outputs from the clean notebook
python scripts/strip_widget_outputs.py

# 3. regenerate the MyST reading copy (frontmatter, note, tags, previews)
python scripts/prepare_book.py
```

The reading copy adds:

- YAML frontmatter for the page title;
- the “Interactive version” note linking to Binder/Colab;
- Markdown image paths adjusted for the repository root;
- MyST cell tags (`hide-input`, `remove-output`, `remove-cell`);
- the nine static default-state previews.

`source/chapter-01.ipynb` stays clean: no frontmatter, no previews, no reading-only note, no MyST tags, and no saved widget outputs. That is what Binder and Colab open. All figures on the reading page have descriptive alt text.

## Deployment

Every push to `main` triggers `.github/workflows/deploy.yml`, which builds the site with a pinned MyST version and deploys it to GitHub Pages. GitHub Pages must use **GitHub Actions** as its source (Settings → Pages).

The Binder environment is built from `requirements.txt`. The first Binder launch can take a minute or two while the image is built and cached.
